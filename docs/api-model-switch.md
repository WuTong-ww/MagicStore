# AI 接口地址、模型切换与次日来客

此前对白实测使用 PJLab 的 Chat Completions 接口，分别测试 `deepseek-v4.1-flash`、`glm-5.3`、`glm-5.3-flash`、`qwen3.8-27b-fp8`。密钥由测试进程环境提供，不写入本文、存档或交付包。

## HTTP 地址和自动补全

设置、直接对话、后台人物创建和 Python 网关上游均支持 HTTP/HTTPS，不再限制 HTTP 只能用于 localhost。可以输入域名、公网/内网 IPv4 或方括号 IPv6，并保留合法端口和代理路径前缀。

|输入|检查后的端点|
|---|---|
|`http://36.140.146.31:23501`|`http://36.140.146.31:23501/v1/chat/completions`|
|`http://36.140.146.31:23501/v1`|`http://36.140.146.31:23501/v1/chat/completions`|
|`http://36.140.146.31:23501/v1/chat`|`http://36.140.146.31:23501/v1/chat/completions`|
|完整的 `/chat/completions` 地址|保持原有路径，不重复添加 `/v1`|
|`https://example.com/proxy/v1/`|`https://example.com/proxy/v1/chat/completions`|

输入框失焦和应用设置时都会检查格式；补全后的地址直接显示，错误在弹窗内就地提示，原可用配置保持。预览和应用都不会自动发送模型请求，格式正确不代表服务已经通过鉴权。同一端点的 `/v1` 与完整地址规范化后相等，留空密钥可保留当前进程凭据；换地址仍需重新填写。未知路径、非法端口、非HTTP(S)协议、混入账号、查询参数、片段或控制字符会被拒绝，不猜测另一个路径或改变协议。

本次使用 Python 和游戏实际使用的 Godot HTTP 客户端，不带鉴权头检查上述公网地址：`/v1` 补全和完整端点均连通，服务返回 **401**。这证明客户端已能访问该HTTP端点，服务仍要求对应凭据；没有向新地址发送此前 PJLab 的密钥，也没有把401当作模型推理成功。带鉴权的生成、独立审核及后台人物生成使用真实本地假服务验证补全后的请求路径。

共享规则位于 `scripts/providers/api_endpoint.gd` 和 `server/ai/api_endpoint.py`，测试与导出范围见[最新验收](verification.md)。

## 新增动态短问题后的复测

咨询区现支持[随对白更新的后续问题](followup-questions.md)，通常8–12字，最多16字。新传输逻辑在原45秒期限内对短暂故障最多恢复一次；认证、格式和事实核验失败不重试。复制模型名称时末尾的排版反斜杠也会规范化。

最终短问题版报告 `.tools/live-followup-models-final-v3.json` 通过真实设置窗口依次切换四模型，再切回 DeepSeek；后续应用均留空密钥。每次切换后的首轮均成功在线并获得2–3条模型问题；实际点击模型按钮五次均完成交谈。另在GLM请求真正等待时，通过设置切回DeepSeek，旧请求返回取消且不写入任何对白、问题、线索或时间，随后继续对话及读档通过。

这轮共11次实际交谈，全部动作成功：9条模型原文通过审核、2条因无来源的反复查看习惯而正确回退。接口均已返回HTTP 200，后两条属于事实保护，不能称为API调用失败；也不能称为11次全部保留了模型原句。严格测试脚本要求每轮在线及每轮保留模型问题，因此这两次保护回退对应4项断言未达，脚本非零退出，原记录保留。

最终22条已批准模型问题平均 **9字**、最长 **13字**；包括本地补齐在内的33个实际按钮都不超过16字。诸如「附言让你想到什么？」「回信现在寄了吗？」可直接引导下一轮，问题不会自己授予线索。85项断言中，配置保留、按钮绑定、短文本、单次收费、取消与读档相关断言通过；上述4项严格全在线断言单列。

11次动作平均等待11.603秒，中位3.072秒，范围2.133–41.353秒，包含两次安全回退。GLM在生成和审核上仍有明显长等待。测量包含生成、审核、保存及两个无界面帧，同机有本地回归并行，不是模型纯生成速度或显示器延迟。样本少且按顺序运行，不作模型排名。

V1保留一次GLM Flash约45秒无响应；V2保留问题标签与事实混淆导致的审核误拒。修正后的提示区分本地已授权的提问方向、实际对白证据和未知答案，没有给模型新增隐藏答案，也没有放松主对白事实核验。最终有限人工检查仍记录了一处轻微过程描写的解释空间，不能据此保证任意输出绝无误差。详细逐轮QA为 `.tools/live-followup-models-final-v3-qa.json`。

以下保留此前接口参数及次日来客修复的说明与历史测量；其中的11/11结果来自加入动态问题功能之前，不能与本轮9条原文、2条保护回退混为一轮。

## 修复内容

同一个 URL 下只修改模型时，设置页留空 API Key 会保留当前进程已填写的密钥。更换 URL 时必须重新填写密钥，避免将旧密钥转发给另一地址。复制来的末尾斜杠、排版反斜杠和模型名称中的「推荐」后缀会规范化；嵌入换行或多余 URL 内容被拒绝，原可用配置仍保留。

修改配置会取消旧对白和旧后台人物任务。未审核的候选不会写入对话、共同记忆、线索或存档；迟到的回复不能覆盖新请求。游戏时钟、当前来客和接待 ID 不因配置变化而改变。取消动作不消耗游戏时间，随后可重新发送。

旧配置下，DeepSeek 能在线回复；GLM 5.3 的一次审核耗尽 45 秒总预算，GLM Flash 和 Qwen 的审核则把 1024 个输出 token 全部用于推理，以 `finish_reason=length` 结束。它们的请求已到达服务，但没有可接受的完整审核 JSON；这与密钥丢失不同。

现在直连和 Python 网关共用一致的模型族策略：

|模型|请求处理|
|---|---|
|DeepSeek|保留关闭思考、生成温度 0.25 的已有配置|
|GLM 5.3 / Flash|保留必要思考，使用 `reasoning_effort=low`；对白每阶段最多 4096 输出 token，生成温度 0.25；人物创建 6144、审核 4096|
|Qwen 3|使用顶层 `enable_thinking=false` 与 `chat_template_kwargs.enable_thinking=false`，在所测接口均获接受|
|其他模型|保持通用参数，不推测该模型支持的特殊选项|

仅接受 `message.content` 中的完整 JSON 对象或单个完整 JSON 围栏。`reasoning_content`、截断、异常完成状态、多个对象或附加解释都不能替代有效回复。独立事实审核和本地权限校验仍然必需；未通过则使用当前获准话题的本地回复。整个对白流水线仍有 45 秒总上限，不会无限等待或无限重试。

参数依据参见 [GLM 官方说明](https://cloud.tencent.com/document/product/1823/132061)、[Qwen 官方配置](https://qwenlm.github.io/Qwen-Agent/en/guide/get_started/configuration/)及 [vLLM 推理输出说明](https://docs.vllm.ai/en/stable/features/reasoning_outputs/)。这些资料用于选择兼容参数；PJLab 的具体行为以本轮真实请求为准，不能仅由其他服务商文档推断。

## 次日来客与等待

自然客流原先允许整天随机抽到零人，而且所有人都可能被排在开门之后。现在自然来客最低每日一位，新规划的次日第一位在 09:00 进入候客队列。已有预约保留，所有来源仍共用每日 20 位上限，候客最多 6 位。

未见面便离开的生成来客不再永久占用预备名额；仍有未来约定的人物继续保留名额，已经保存的人物资料不会删除。后台目标为预备 6 位、每日最多新入档 8 位。空前台可直接「等一会儿」，最多推进 30 游戏分钟，临近打烊会缩短；等到来客后入口隐藏。并发、配额和审核流程不在游戏界面展示。

本地整合测试实际运行新建、结束接待、连续三次打烊次日、读档、从候客队列接待新人物；每次保留独立人物与接待 ID。前台等待按钮也通过真实动作验证保存、资源不变及打烊边界，并在 1280×720 和 1920×1080 实际渲染检查。

## 复现与测量范围

真实切换测试使用同一局、同一来客、同一接待，依次切换四模型，再切回 DeepSeek；每次包含话题按钮和自由输入，后续切换不再填密钥。结束接待后实际进入次日，从真实队列接待新顾客，再对话和读档。

```powershell
# 事先在当前进程提供 MAGIC_LIVE_API_URL 和 MAGIC_LIVE_API_KEY。
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/dev/run-live-model-switch.ps1 -ReportName live-model-switch.json
```

报告逐轮保存在 `.tools`，包含审核结果、完成状态、服务端 usage 和分阶段耗时；不包含密钥或原始推理。若任何一轮使用本地回退，严格测试脚本返回非零，保留原始失败记录。真实测量包含实际生成、独立审核、保存和两个无界面处理帧，未测显示器延迟。样本很少，不能据此保证上游稳定性或模型永不误判。

## 此前复测结果（动态问题功能加入前）

最后一轮 `.tools/live-model-switch-final-v3.json`：**11 次对白全部在线生成、通过独立审核并保存**；其中 10 次发生在同一位顾客、同一次接待中，另外 1 次在实际打烊次日接待新客后完成。同一次接待内切换设置保留当前密钥和游戏状态，四模型均覆盖按钮提问及自由输入，切回 DeepSeek 也成功。次日 09:00 有一位新顾客进入真实队列，接待、对话和读档保持一致。

|模型|本轮同一接待样本|平均动作等待|范围|
|---|---:|---:|---:|
|DeepSeek|4 次（开头和切回各两次）|2.810 秒|2.406–3.842 秒|
|GLM 5.3|2 次|5.180 秒|3.054–7.306 秒|
|GLM 5.3 Flash|2 次|1.935 秒|1.757–2.114 秒|
|Qwen|2 次|2.608 秒|2.340–2.877 秒|

另一次次日新客对白为 DeepSeek，1.112 秒。全部 11 次平均 2.891 秒，中位 2.445 秒。它们是极少量、按顺序运行的同题切换样本，不能当作模型速度排名。此前同一接口上的 GLM 有过约 42 秒才成功的回复，以及约 45 秒超时后的本地回退；保留在前轮报告中，最终短样本不能证明波动已消失。

传输成功也不等于文字没有问题。上一轮 11 次虽然都在线，一句「我每天去看一眼」未有来源却被审核放过，随后其他模型沿用了这句共同记忆。已补充固定频率/习惯的来源检查及生成、审核提示，在最早入档之前拦截此类句子；有实际人物资料支持的同类习惯仍允许。原问题报告 `.tools/live-model-switch-final-v2.json` 原样保留，未删除或改写已有对白记录来制造通过结果。

修复后最后 11 次逐句核查未再发现这类新增习惯、身份变化或隐藏材料提前披露。重复询问同一本书时，模型会承认此前已经聊过；这个控制场景用来验证上下文连续性，不代表已经覆盖多样化闲聊。其他人物及跨日回访的独立实测范围见[原创新来客流程](people-generation.md)。
