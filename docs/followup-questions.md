# 随谈话更新的后续问题

咨询区不再一直摆着同一排问题。在线对白生成时，模型会同时写出通常 2–3 个玩家接下来可以问的问题；通过独立审核后，替换当前来客的问题按钮。点击发送的是完整问题原文和对应的本案话题，不会把问题本身算作新线索。

问题来自当前实际可谈的方向。创建提示、其他话题的答案、未开放的隐藏材料不会为了生成按钮而一并发送。刚刚获得线索而开放的新方向，可由本地问句补入一个位置；模型少给、漏给或建议无效时，当前可用的本地问题补齐，最多三条。尚未开放的话题不显示。

## 模型契约与审核

同一轮生成返回：

```json
{
  "intent": "work",
  "reply_text": "纸页得一张张慢慢晾干，急不得。",
  "evidence_ids": ["topic:work"],
  "followup_questions": [
    {"topic_id": "letter", "text": "回信让你最犹豫的是什么？"},
    {"topic_id": "work", "text": "修这本书时，你最费心的是哪一步？"}
  ]
}
```

这只是结构示例，具体答案仍按本案真实来源生成。旧三字段回复继续兼容，问题缺失不使已经有效的对白报错。该功能不增加一轮模型请求：按钮提问仍为生成及独立审核，自由输入再加原有的话题识别。

新增的 `question_topics` 只含当前授权的 `topic_id` 和 `label`，用于选择方向；它不含这些方向的答案，标签也不能作为顾客新增事实的证据。问题从玩家的角度发问，需要贴近前文、点明所问对象或动作，避免把附言感受硬标为回信、用“这句话”之类泛指掩盖话题歧义。不要写攻略、任务提示或客服式套话。

每条问题通常 8–12 字，最多 16 字，直接提问，省去多余铺垫。同一方向和同一文案去重；仅扫描候选前十二项，保留最多三条。超长、未知话题、其他来客的话题、格式错误、换行、不可见控制符、URL、标记代码与内部字段被剔除，不硬截断句子。剔除坏建议不影响合法主对白。

规范化后的整份候选进入独立审核。审核同时检查对白和问题：问题里的事实前提也必须有依据，不能暗示未披露案情、预先确定结局，或将玩家猜测当事实。任意语义审核不通过时，整份候选使用原有安全回退；不能悄悄展示未经批准的问题。审核指纹包含问题文字、方向与顺序，修改后不能沿用原批准结果。

## 界面与存档

问题按钮保持 18 号字体，长中文正常换行，在 1280×720 和 1920×1080 实际渲染检查。相同话题 ID 而文字变化时也重新绑定回调；忙碌时禁用，发送前再核对当前接待和当前问题。上次接待留下的旧回调不能误发给另一位顾客。

只有成功保存的对白才能更新问题。`visit.followup_questions` 与 `followup_action_id` 绑定已保存的原对话动作；写盘失败保持旧对白、问题、记忆和时钟，重复动作不会重新生成。读档恢复本次问题，换存档或新来访不沿用另一场接待的建议。旧存档无需新增必填字段。

## 中途切模型与临时故障

首页和游戏内同一个设置窗口可切换模型。同 URL 留空密钥会保留当前进程已填写的密钥；换 URL 要重新填写。配置变化取消旧请求及重试计时器，旧候选和旧建议不能写入当前接待。

对白流水线可在原 45 秒总预算内，针对短暂断连和 408、429、500、502、503、504 做最多一次短暂退避重试。重发相同阶段和相同请求正文，失败尝试不会提交为另一次交谈；取消或切模型会使旧重试失效。较长或无法安全解释的 `Retry-After` 不提前重试。认证失败、格式无效、截断或只有推理、事实审核拒绝均不重试。上游长时间无响应仍会在期限内回退，不能承诺远端服务永不超时。

实现位置：`scripts/providers/dialogue_policy.gd` 和 `server/ai/gateway.py` 管理生成、问题过滤与整体审核；`http_dialogue_provider.gd` 管理传输与恢复；`game_state.gd`、`save_service.gd` 管理权限、原子保存及读取；`scripts/ui/consultation.gd` 管理按钮更新与点击。
