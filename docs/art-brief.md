# 零点杂货铺本月全量分镜与美术制作单

**目标验收日为 2026 年 11 月 30 日。** 本月交付七个主场景、角色与捏脸、全部术式、前世、商品原料和各玩法的界面状态。分镜是要在游戏里看见的交互状态，一张主图配合前景、人物和控件可覆盖多个镜头。人物细节、商品外形、素材数量和构图是制作建议，已有人物和场景以仓库为准。[三人技术分工](tech-workstreams.md) · [现有功能](features.md)

## 美术基准

保留现有深青底、暖金提示和米色文字的关系。可从 `#13262D`、`#D5BD86`、`#E6E3D4` 起稿，在前台与咨询区先定木纹、布面、旧纸、金属与皮肤的材质样张。圆窗、店招月相和桌灯作为店铺的辨识物。柜台的磨痕、账本、修书纸签、杯垫印和沙发褶皱提供生活细节。店面和室内沿用一致的门窗方向、光源和店招比例。[前台占位图](../assets/shop_front.svg) · [咨询占位图](../assets/consultation.svg) · [界面主题](../themes/midnight.tres)

建议空间走向为街道进门到第一人称柜台，柜台侧有储物柜，门帘后是咨询沙发与矮桌，工坊可从前台进入。原料商店和采集地使用独立场景，各有返回入口。窗光、灯和门牌单独出层，以开店、打烊或时间变化切换。界面文字、数值、提示和按钮由 Godot 绘制。

## 交互分镜

F01–F24 为制作及验收编号。交易、学习、采集、事件和回访可以在不同日期出现，分镜按玩家能触发的状态绘制。

| 镜号 | 玩家看到或做到什么 | 构图、叠层与界面状态 |
| --- | --- | --- |
| F01 看见店铺 | 启动时看见店面并进入 | S01 全景，门和窗灯做动态层，店名留安全区。可切营业牌和打烊牌 |
| F02 开档与续玩 | 新建、选择档案、继续和备份恢复 | S01 背景叠存档簿。区分空档、已有档、损坏提示、恢复确认 |
| F03 捏脸 | 更换部件、预览、确认玩家外貌 | 半身大预览与来客卡小预览，部件分组、前后层及确认态清楚。重开可对照原脸 |
| F04 等客与客满 | 零客、来客、队伍爆满、预约或等候离开 | S02 同机位叠来客剪影及列表。可见等候、接待、预约、离店；读字和等待模型时耐心显示不走动 |
| F05 认识顾客 | 看顾客职业、来意、已知关系、熟悉程度和推荐人 | S02 顾客卡。用区分明确的文字和图标表现问卜、购物、两者兼有。档案扩展为生日、星座、MBTI、偏好等可见内容 |
| F06 请入咨询区 | 入座，与顾客第一次或继续谈话 | S03 从店长座位看对面沙发，林照晚可用平静或犹豫表情。左侧话题和输入，右侧服务栏 |
| F07 约定报酬 | 确认本次正式问卜的金币或物品报酬 | S03 报价面板展示类型、数量、精力和时间。区分待确认、已付、支付不足，待结算时结果区域保持未揭示 |
| F08 提问与回应 | 点击选项或输入中文，获得线索、需求、剧情反应或澄清 | S03 对话框和角色表情。给「对话处理中」「服务繁忙」「重试」「使用本地回应」留控件与文案位置。等待时保持游戏时钟可见且静止，熟客追问显示此前可见记录 |
| F09 使用术式 | 选择已学术式，执行它对应的玩法 | S03 术具区按下表切换。已锁、可用、结果、保存后重看共用页框，术式互动各自可辨 |
| F10 整理线索 | 查看证物并区别已知信息和个人假设 | 手记叠层，顾客陈述、工具线索、玩家假设各有来源标识。只有获知后才显示对应证据与事实 |
| F11 留预测与建议 | 记录对象、时间窗与预测，给出建议，看顾客采纳或拒绝 | S03 手记页显示「我对顾客说的话」和待验证状态。表情与短句表达反应，保留再查看入口 |
| F12 前世片段 | 使用技法看到片段、提出解释、确认跨世关联 | 同一套片段叠层支持未解、解释、已确认。今生与前世通过时间标记和可辨识人物特征衔接 |
| F13 购物或登记需求 | 单独买商品，或在问卜后加购，或缺货登记需求 | S02 或 S03 交易小面板。展示商品、价格、缺货、需求已记。占卜、购物和赠礼各有独立收据样式 |
| F14 开储物柜 | 查看商品、原料、数量、来源和用途 | S04 关闭转打开，图标固定大小。空格、选中、可用、数量不足有明确状态 |
| F15 研究和制作 | 从需求解锁配方，用原料制作 | S05 配方及工作台叠层。可显示缺前置、缺料、可制作、完成；时间与精力的变化留在状态栏 |
| F16 采购与原料出售 | 到原料商店买入或直接出售同一库存的原料 | S06 柜台加买入、卖出页签。选择数量、确认、缺货和余额不足。购买前后和储物柜数字一致 |
| F17 出门采集 | 选材料点、看条件与耗时、采到原料 | S07 主图叠采集点状态，可采、已采、未满足条件。回店后在同一库存看见所得原料 |
| F18 使用商品 | 查看用法并使用商品，看到属性变化或剧情选项 | 商品详情卡和使用记录。三类用途可用文字标签；提供使用前、使用后、事件或解决方式解锁提示 |
| F19 学习术式 | 选学习项目、支付成本、获得新术式 | 学习页显示前置、金币、精力与时间。需要未学、可学、进行结果、已掌握状态，图标与咨询一致 |
| F20 休息与打烊 | 精力不足休息，或结束一天后进入次日 | S02 休息提示与灯光叠层。显示原时间、目标时间和精力变化。候客或预约受影响时有提示位置 |
| F21 事件与等待反馈 | 推进至约定事件时间，观察已有证据或继续等待 | 手记时间线可显示未到期、待反馈、未收到反馈。用中性状态表现未知，已有证据才展示可判定结果 |
| F22 回访与后果 | 同一顾客归来，查看预测结果、关系变化、复盘、礼物或转介绍 | S02/S03 复用原外貌，回访页连接原接待。符合、偏离、证据不足区分；奖励和关系变化各有说明及账目入口 |
| F23 参考家族分批来店 | 先认识一位家族成员，之后见到另一位并查关系 | 用同一世界的服饰与家族小标记保持识别。两位成员轮廓和装束可辨，关系图逐步展示玩家已知成员 |
| F24 查看经营风格 | 打开基于实际操作的娱乐性报告 | 手记式页面展示风格、样本数量、观察项和可回看的接待。报告文字与 NPC 的 MBTI 档案使用不同标题与语气 |

| 前世出场人物 | 建议至少两张片段图或两组可组合的前世剪影 | 能用已确定的特征认出今生人物，同时区分过去的身份、服装和关系。画面隐藏尚未由规则确认的身份信息 |

胸像建议用 **720×840** 的透明 PNG，同一头心、眼线、下巴、肩线、光向和裁切。现有前台头像区约 **83×100**，缩到该尺寸也要可辨。部件层次统一为后发、脸与肤色、五官、前发、服装、配饰。把外貌预设和表情命名交给 A，至少检查一次组合叠层、另一次读档后的同角色复现。[现有林照晚头像](../assets/portrait_lin.svg)

建议物品图标为 **256×256 透明 PNG**，在约 **48×48** 的显示区检查轮廓。原创样例先定三视重点、颜色、材质、光向、阴影和留白，再以此生成候选，检查相似项、形变、可辨识度与来源。美工选定一组可用候选并完成清理，C 按资源键导入对应配方、交易和背包。参考家族、人物和素材均记录确认后的来源与作者。[素材许可记录](third-party.md)

游戏自建的 Qwen3.8-27B 服务承担文字对话和叙事候选。美术扩图沿用原创样例与独立图像生成流程，成品审核后导入。需要共用 A100 时，把扩图安排在推理维护窗口。角色生成使用已交付的组合头像部件键。[单卡部署方案](ai-deployment.md)

每个素材记录 **资源键、镜号、使用状态、像素尺寸、裁切与锚点、作者和来源**。建议前台用 `scene_front`，角色表情用 `npc_lin_neutral` 等稳定键。A 接人物和外貌，B 接术式和案例素材，C 接场景、物品及通用控件。背景、前景、人物、灯光和互动道具可独立替换。最终截图检查人物脸部与文本未被遮挡，未知剧情通过图像与文案都保持未揭示，失败、等待和成功状态无需仅靠颜色判断。

逐镜验收可分给三组。A 检查捏脸、来客、AI 对话、回访、家族和报告。B 检查咨询、报价、证据、全部术式、预测、前世和事件结果。C 检查场景入口、存档、交易、四个经营场景、学习、精力和打烊。共同出现的画面由对应组在同一试玩包中联合检查。
