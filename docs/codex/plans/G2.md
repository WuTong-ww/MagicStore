# G2 可配置家族库计划

## 目标与范围

依据HANDBOOK G2全部条目：将单例二人模板扩为可配置家族库，完整关系网一次入档、成员分批登场；只增加一个三人原创测试占位，不编写任何作品人设、台词或剧情。A4任务f2e0d13及META7f932d9已普通Git推送；继续codex/round2-clean，不改main／旧round2，不新增依赖或图源。

保守选择：占位在正式客流关闭，生产触发概率0；测试显式开启。活跃家族按仍有未相识／首次接待待办的成员计，不因没有真实结算来源的开放目标永久占槽。默认特殊实际到店占比上限12%，首次／回访／预约／推荐均纳入同一保护；分开计划预算和已发生到店计数，未到时间的普通计划不撑大分母。旧统计保留原义，新统计从迁移后的明确时间／到店ID计数，不编造历史。

## 文件与单一所有权

- 家族库纯规则：新scripts/people/family_library.gd、data/people/family_library.json、families/family_placeholder.json与对应规则测试。负责每个JSON校验、已满足条件模板、稳定成员／边／目标ID提案，完整验证后才返回。来源备注与原作字段始终私有。
- 事务与调度：People、PeopleBridge、GameState、SaveService只有一位owner。schema7及1–6内存迁移，保留旧demo两人／一边及既有人物ID、生日、关系历史、已排计划、A4外观和生成式身份hash；失败／重试／重放／重开真实动作测试。不能把旧二人实例替换成三人占位。
- 双端对白保护：policy／http／mock与Python gateway、独立本地策略JSON及测试。只公开改写后身份／口吻／边界，不把source_work、reference_character、reference_note、隐藏图或屏蔽原文发给生成／审阅模型。过滤本地输出及审核后绑定候选；测试禁词用合成标记，不编真实作品词表。不得修改生成式人物v1/v2 canonical hash协议。
- Root负责本计划、填写指南docs/families.md、features、run.ps1入口、最终测试／图审／体积／提交。必要档案UI只消费public_view；已有关系装饰图烘焙问号在本任务关系展示中撤下，保留历史文件和资源记录，不顺手重画／修A4选中页签。

## 先冻结的最小接口

FamilyLibrary提供load_config／config_valid／template_valid、eligible_templates(最小world_context,library)及instance_proposal(template,save_id,existing_ids)。纯规则owner先发精确返回结构给事务owner，二者协商后记录接口，不并写People。

技术键包含template_id与成员／边／目标稳定key、save域；数组重排不改ID，同名member key跨模板不碰撞。旧ensure_family注入二人fixture保留兼容门面。新模板固定外观走A4 selection_valid；旧持久外观继续appearance_valid，不因帽子新互斥重抽或拒读。

初始问题由member_goals数据提供owner／subject／edge／question／来源。只实现有明确真实动作或G3结果来源的状态变化；没有来源的目标保留open，不以“聊过一次”假装完整任务追踪。图实例化不等于关系已向玩家披露；G3修改每条实际边，UI仅显示revealed关系。

## 实施与验收（最多三轮）

1. 先增加能失败的真实规则／迁移／协议负例，再最小实现。保留历史二人和G1分布断言，禁止放宽阈值或删旧用例跑绿。
2. 验单家族schema／重复key／未知端点／无效条件／外观／碰撞，无半个家庭入档；同成员key的两个测试模板、数组重排、重复触发均稳定。
3. 占位三人按每日与同时段上限分批；没接待就离开不误记相识；已见成员回访沿用npc_id／外观；真实到店特殊比例不超过配置12%，含特殊回访；关闭库不新增G1随机消耗或改旧计划。
4. 三条边分别经真实G3 effect改变；保存失败、同ID重试／重放、重新加载均不重复结算。旧schema1–6及旧demo原ID／图／历史／外观保留，load不写盘。
5. 双端禁名／原文过滤、候选篡改、fallback、真实127.0.0.1 HTTP请求不泄漏源材料／未揭示图。家族成员模型只拿改写后的白名单人设。
6. 所有新增JSON都有validator；运行scripts/dev/run.ps1 -Test完整全绿。引擎单通道，APPDATA等隔离；回环按已授权环境运行。若改UI，实际shop_ui双尺寸及必要关系档案截图，root逐张五项检查，最多六quality85 JPG，其他只.tools。
7. 更新features、PROGRESS及UPLOAD_STATUS；测试后以[G2]提交并普通push。三轮仍未过明确部分完成，不无限重试，不提前进入G4生产或最终REVIEW_PACKET。

## 已冻结接口与决定

纯库已实际106/106：磁盘registry为version/enabled/template_paths/policy，加载后加templates。5API与proposal字典按docs/families.md及实际源码；proposal含family、成员／边／目标字典及局部key到全局ID映射，任一冲突整体失败。统计episode采用arrival_id_and_at。

Root在实施前纠正预约预算：新计划／承诺前预留R，actual S/T只计已发生到门，使用(S+R+1)/(T+R+1)<=cap，不让未来普通计划撑分母，不在已确认预约到点时静默取消。迁移旧承诺保持ID/at/同意来源，无法恢复的历史独立标legacy例外；配置与统计可回退，旧档不改写。30日真实分布初验因回访先占预算使第三成员饿死，改新family分支先初见后回访，既有普通G1／旧二人路径不动，重验3人齐。

UI范围由root接手：只撤下PeoplePanel既有relationship_graph装饰节点，其原图有烘焙问号且不代表真实关系；保留原资产／来源记录，已有动态关系文字继续只消费public_view。没有新画关系图、家族编辑器或修改A4灰白页签。

独立接线检查发现两个接口缺口，按手册作最小保守裁定：①每成员必须恰有一个初始问题，纯库validator拒绝空／未覆盖的member_goals，避免“配置合法但无法实例化”；②已有通用家族没有真实关系揭示入口，不能为截图伪造revealed。新成员开始真实接待时，开场保留作者问题，再由JSON通用句式说明自己与问题对象的关系，只揭示该问题的一条边，来源绑定保存成功的start动作／visit／开场顾客陈述。其他边继续私有；陈述不升级为验证过的世界事实。回退可关闭库／该披露接点；旧林与生成式人物规则保持。

Root一度仅看public_profile误判personality会显示技术ID；核对新成员构造后确认当前已是personality自然文、personality_id枚举，故不作无谓字段重构，增加两种投影分别正确的回归。此项不是已复现的生产故障。

同样，HTTP._valid_reply片段未直接验主回复，但完整_on_completed随后已有scoped Policy._text_safe并使用本地guard；root撤回重复修改要求，以真实HTTP的local-only旧来源词负例确认整链。不能把函数片段审查的假阳性写成已修复生产漏洞。

前置家族成员的真实npc_id含存档域，策划无法预写。保留既有trust_requirements结构，npc_id额外约定稳定本地别名family:<template_id>:<member_key>；运行时仅为已相识成员加入必要known_trust投影，不向模型或玩家显示该键，不改存档身份。用未见／低信任／达到门槛的负正例验收；回退只需删该别名条件／关闭库。

内容边界：占位目前沿用archive案例容器，自己的问题／家人对象已动态绑定，旧案例标题／后续旧物文案并非完整家族专属剧情。三边G3事务使用测试内合法运行时规则绑定实际边，验证消费与幂等，不能夸称正式事件内容已配齐。后续正式家族事件仍需局部关系引用到实例ID的模板接线；不要求策划预写含存档域的rel_id，不自行创作作品内容。该项与严格首屏关系显示一起列为部分完成边界。
