# 收到的网页版补充（2026-11-24）

来源：本聊天技术总监追加验收，已上线第二轮地址 https://wutong-ww.github.io/MagicStore/ ，实测浏览器视窗1280×529。本文件替换原目标的R3-WEB规格，保留既有工作与原任务顺序。当前R3-POLISH尚未开始，因此下面1–3项在POLISH一并完成，4–8项在WEB完成。

1. 所有界面文字使用随包嵌入的霞鹜文楷和等宽数字字体，覆盖全部用到字符。脚本扫描全部JSON与脚本的中文字符，字体覆盖100%。所有图标改SVG/PNG图片，移除Unicode图标依赖，解决前台状态与底栏缺字方块。
2. 修复网页版弹窗、侧栏ScrollContainer的鼠标滚轮，加入测试，不能只接受拖动滚动条。
3. 高度<640时侧栏为覆盖式全高抽屉；对话框高度≤视窗45%，人物随之上移。所有面板有最小可用高度，空间不足整体缩放，避免挤压。验收截图1280×529、1366×768、1920×1080，包含咨询脸部与工具抽屉。
4. 存档簿打开时隐藏其他面板，首次进入不让右侧“灯下的杂货铺”与“收起手帐”半露在后面。
5. 针对首次加载约40秒，量取现行包体积，再移除Web不需要的旧场景、未使用运行副本、工程预览图，采用WebP或有损导入。审阅包给实际前后体积；构建后验证动态JSON路径所需资源仍完整。
6. Web不包含API密钥或私有服务地址；对话和案件全走本地固定剧情、备用模板。
7. 音乐不在公开仓库再发布；缺assets/audio/music时静音。文档说明本地带音乐构建方法。
8. GitHub Actions在推送codex/round3时自动导出并发布Pages的/preview/预览，保留当前正式页面。main合并后才更新正式页面；本轮不改main、不强推。Pages的整站部署不能用只有preview的产物替换现有根站，正式内容保留必须验证。

另两条旧版试玩现象作为CASE/LOOP验收依据：旧塔罗要四个下拉、两次确认且输出整页文字；静止不操作时时钟和来客都不推进。新默认流程应能按钮提问、实际翻牌、证据推理，并在上一位结束后立即按“请下一位”接待，无等待客流。保留原目标按接待动作推进氛围时钟的设计。
