## 新层级方案的只读核对

检查 `scripts/shop/scene_visual.gd`、`scripts/shop/shop_screen.gd`、`scripts/ui/consultation.gd` 与 v3 配置；不把代码算术核对当成第二轮视觉通过。

- 当前 v3 配置 `art_root_z=-2048`、`layer_z_bounds=[-1024,1024]`：美术有效 z 为 -3072～-1024。即使本地 z 为正，也低于 UI 的0平面；热区、热点标签和库存格以最高美术+1摆放，当前上界为 -1023，仍低于UI。负层同样保持原局部顺序。底图本地-4096在有效z下限处，仍位于这些活动层之后。
- 咨询头像仍作为 `SceneVisual` 子节点，本地z=10；沙发遮罩被约束在头像之上、抽屉/对白局部阈值之前（当前11～19）。当前有效z分别为-2038和-2037～-2029；纸抽屉/对白是外部兄弟控件z=20/30，所以不会被这些前景压住。这个方案保留头像与沙发的相对层级。
- v2 的场景根z仍为0；库存格额外z调整只在v3执行。原v2切片布局不因本修复改变。
- **复核时发现的配置边界缺口（已交主代理）**：初始校验只用 `art_root_z+upper+1<0`，漏掉 `interaction_z_index()` 从0开始求最大值及咨询头像/沙发保留z。复核期间已读到主代理把热区预算改为 `art_root_z+max(0,upper)+1<0`；头像本地10、沙发可升到19仍须纳入边界。例如所有美术层z=-1、bounds=[-1,-1]、root=-2可通过该算式，但头像有效z=8、沙发遮罩可到9，会重新跨UI。当前实际默认参数安全；后续需以专项RED/GREEN确认头像保留范围也受约束。本文不声称该后续修复已完成。
