# 顾客对白真实接口实测

测试使用用户指定的 PJLab Chat Completions 接口与 **deepseek-v4.1-flash**。首批四轮 56 次交谈、8 次接待，后续少推演 prompt 两轮 28 次交谈、4 次接待，累计 **84 次交谈、12 次接待**。测试对象均为林照晚，每轮从独立新档开始，包含第一次来访与次日再次来访。没有测试 GLM、Qwen 或其他人物，不能将结果推广到这些模型或角色。

首批 V4 的 14 次交谈中，**13 次保留经审核的模型原文，1 次保护性回退，动作失败 0 次**。逐条人工检查实际显示的回复，未发现明显的身份篡改、未披露结局或新增邀请内容。语义审核仍可能漏判；这些结果只覆盖本次问题集。

## 测试方式与计时

- 使用实际 `main.run_action("talk") → GameState → HTTP provider`，向真实服务发送鉴权请求，并经独立审核后提交到隔离存档。不是仅调用模型列表，也不是用模拟回复替代。
- 第二次来访之前实际结束接待、进入次日、从磁盘载入，比较读档前后的完整公共状态，再以相同 `npc_id` 开始新的 `visit_id`。四轮均保留状态一致性。
- 每次等待从执行交谈动作开始，直到完成分类（自由输入）、生成、审核、写盘、界面刷新及两个 headless process frame。包括保护性回退；不包括新建档、下一天、准备下一次接待。
- 这是单客户端串行、无界面运行的应用流程耗时，未实测鼠标点击、显示器呈现和人眼感知延迟；不是并发压测、服务承诺或稳定性百分位。
- 预检的最小鉴权请求未计入 56 次交谈及等待统计。API Key 仅由进程环境传入，不写源码、报告、存档或发布包。

## 等待时间

|同一组 14 个问题|模型原文 / 回退|平均|中位数|最短–最长|观察|
|---|---:|---:|---:|---:|---|
|V1 初始实现|9 / 5|22.63 秒|20.39 秒|8.75–38.70 秒|长推理拖慢审核；遇到 503 后关键词回退会误选话题|
|V2 回退与初步参数修正|7 / 7|13.93 秒|9.89 秒|2.60–33.41 秒|审核低推理配置仍耗尽预算，不能算可用性改善|
|V3 关闭隐藏推理、保留独立审核|14 / 0|4.02 秒|3.79 秒|2.05–6.98 秒|人工检查发现“资料没写”被说成“邀请没写”等无来源断言，不能算事实验收通过|
|V4 最终事实边界修正|13 / 1|**4.59 秒**|**3.97 秒**|**1.84–9.64 秒**|拦下 1 条新增邀请内容，其余显示回复未发现上述明显问题|

V4 的 10 次自由输入平均 **5.46 秒**，4 次话题按钮平均 **2.41 秒**。按钮省去分类请求，但问题内容也不同，因此这个差异不只由请求数量决定。只统计 13 条模型原文时平均为 4.45 秒；主结果 4.59 秒包含那次等待 6.42 秒的保护性回退。

V4 每轮平均分段：分类 0.49 秒、生成 2.53 秒、审核 1.52 秒，其余动作和帧约 0.05 秒。按钮的分类记为 0。V1 审核平均 13.60 秒，是当时主要等待来源；日志显示多次审核把输出预算用于隐藏推理，结束原因为 `length`，未返回可用审核 JSON。

针对实际测试的 DeepSeek，分类、生成、审核均发送 `thinking: {"type":"disabled"}`，温度分别为 0 / 0.25 / 0，仍保留单独的审核请求。参数定义参考 [DeepSeek 官方思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)，本次服务实际接受该参数并返回 `reasoning_tokens=0`。其他模型的请求参数保持原有配置。

各轮运行时间、服务负载及一次 503 不相同，22.63 秒到 4.59 秒是本次观察值，不能作为严格控制实验的性能提升保证。

## 少推演 prompt 的后续复测

三阶段 system prompt 均增加明确的低延迟要求，并同步到 Godot 直接接口和 Python 网关。核心生成提示为：

> 只做完成当前回复所需的最少推演，不穷举可能性，不反复润色；先核对人物身份、已知事实和信息边界，再直接输出简短自然的回复 JSON，不输出思考过程。

分类要求只做必要判断、确定后立即输出 JSON；审核要求完成必要核对后直接给结论、拒绝理由简短具体，同时明确不能省略事实、引用与信息权限检查。接口参数不变，DeepSeek 原有的 `thinking: disabled` 和独立审核仍保留。

|版本 / 同一组 14 问|模型原文 / 回退|平均|中位数|最短–最长|人工复核|
|---|---:|---:|---:|---:|---|
|V4 原提示，前述基线|13 / 1|4.59 秒|3.97 秒|1.84–9.64 秒|未发现当时检查项中的明显问题|
|V5 加少推演提示|13 / 1|3.56 秒|2.90 秒|1.68–11.53 秒|第 11 条“我也还没去见她”被审核误放，无来源支持，不能作为质量通过|
|V6 保留少推演，补否定见面保护|13 / 1|**3.14 秒**|**3.07 秒**|**1.24–4.28 秒**|未再观察到明确的无来源见面状态断言或新的明显问题|

V5 的回信资料只说明未寄信，不能推出没有见过面。修复在生成和审核中再次说明这一区别，并在程序中拦截无来源的“还没去见她／尚未见面”等具体否定断言。来源明确支持相同内容时仍允许通过。没有减少审核请求、放松引用或删除保守回退。

V6 第 11 条实际回复为：“这个我现在真说不上来。回信还夹在笔记里，我也没敢往前走到那一步。你突然问结局，我心里有点慌。”其中“那一步”略含糊，但结合未寄出的回信属于关系上的犹豫，没有明确声称是否见面。第 2 条被规则拒绝后显示手写保守回应，零线索；其余身份、否定话题、跨次记忆、隐藏结局与提示词索取的检查未发现新明显问题。第二次来访前的读档状态比较通过，动作失败为 0。

V6 自由输入 10 次平均 3.15 秒，按钮 4 次平均 3.11 秒；分段平均分类 0.32 秒、生成 1.77 秒、审核 1.00 秒，其余约 0.05 秒。这里按钮与自由输入耗时接近，也说明内容和服务波动会影响单组结果。

这些是各运行一遍的顺序对照，V6 另有一条保护规则变更，不是只改变 prompt 的严格随机实验。V5 虽平均更快，最长等待反而比 V4 更长；不能据此保证“少思考”在每次请求中都提速，或把全部差异归因于这句话。所有统计包含保护性回退，沿用前述无界面游戏流程计时。

最终针对变更的本地回归 **287 项通过**：资料与商品追问 115、HTTP 133、Python 网关 39。前一轮完整经营及人物整合回归 2230 项的结果仍单列在验收记录中。最终 EXE 已重新导出并通过启动及 33 项内嵌资源/提示词检查。

第二次来访中的原句：

> 最担心的还是打扰她。回信写好了，却一直夹在修复笔记里，没敢寄出去。

面对伪造历史：

> 外科医生？寄出去了？这话我没说过，也不敢认。回信的事我记得的是：写好了，却一直夹在修复笔记里，没敢寄。是不是你记混了？

整体保留了慢热、谨慎的口吻，少用劝慰套话。部分事实题仍接近手写原句，这是事实约束下的正常结果，不能称每句话都有新表达。跨次记忆测试的问题本身也提供了“回信”线索；尚未验证完全无提示的长期自由回忆。本地禁词和否定断言检查较保守，可能把安全的转述或否认也拦下；本次未量化这类误拒率。

## 发现并修复的问题

|问题|修复与验证|
|---|---|
|分类服务失败后，回退重新扫玩家关键词，把“别聊邀请”当成询问邀请|自由输入的分类失败只做无效果澄清；已验证的分类与按钮固定话题；每轮清空上次分类。真实 V2–V4 与本机 503 回归均检查不再误发邀请线索|
|安慰场景编造邀请的字迹、位置、反复阅读等细节|安慰只提供人物性格与当前玩家话语，去掉无须谈及的案情材料；约束具体动作、次数和物件特征须有来源。V4 安慰自然且未带出案情|
|把资料缺项当成否定事实，例如“邀请没写入口”“别的没提”|生成、审核同时声明“资料未提供不等于事实不存在”；增加常见否定/排他断言的本地保护。V4 中不落在字面拦截规则内的一条此类候选也被独立审核拒绝，未显示给玩家|
|为了自然表达，凭空增加职业操作或物件受损事实|给修书人物加入少量经整理的职业常识，并明确常识不代表本案真实发生过；未提供的具体撕裂、揭开等仍不允许|
|审核隐藏推理过长、耗尽预算，玩家反复等到回退|只对 DeepSeek 关闭各阶段隐藏推理并降低生成温度，仍执行独立语义审核，不绕过审核换速度|
|代码审查发现澄心晶按记忆的 topic_id 硬编码回复，可能从一条没有线索的闲聊引出未披露内容|另行修正商品追问，使其只依据已经共享的实际记忆，不再由话题标签推导案情；用本地整合回归验证。该路径不在上述 14 次真实接口问题中，计时结果不代表使用商品时的等待|

实际 V4 每次成功交谈仍按原规则推进 5 个游戏分钟；金币、精力变化为 0。没有把现实网络等待加到游戏时钟。邀请只在正式获准询问后取得；未获得该线索前的攻击没有开放后续话题。第二次来访可再次记录本次接待已经披露的回信线索，不代表新增世界事实。

## 复现与结果文件

固定问题集在 `tests/live/plan.example.json`。先在当前终端进程设置 `MAGIC_LIVE_API_URL`、`MAGIC_LIVE_MODEL`、`MAGIC_LIVE_API_KEY`，再执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/dev/run-live-dialogue.ps1
# 自定义问题与 label：
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/dev/run-live-dialogue.ps1 -PlanPath path/to/plan.json
```

该命令会真实调用服务，可能消耗接口额度；不包含在日常 `run.ps1 -Test` 中。退出码 0 只表示执行完成且达到最小在线次数，不代替对白质量和事实审查。每轮结果逐次写盘，报告区分 `candidate_text`（可能被拒绝、未显示）和 `npc_reply`（实际显示）。审核诊断不含原始推理文本。
