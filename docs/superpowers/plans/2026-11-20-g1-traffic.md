# G1 每日客流实施计划

**目标：** 按任务 G1 实现可复现的泊松自然客、零客日、双波峰与集中到店，并保留既有日计划。

**约束：** Godot 4.6.3 / GDScript / Compatibility；状态只在 GameState 保存事务内结算；新增配置与文案放 JSON；旧档仅内存迁移，下一成功动作落盘。

- [x] 客流规则：templates.json 配置期望值各项系数、天气、双峰底噪、burst 与满员策略；people.gd 实现并校验，bridge 独立传入口碑与限时客流加成。
- [x] 存档：schema4 只补流失统计，不改变旧 days/arrivals；验证加载、保存失败、重试与再次加载。
- [x] 前台：零客文案与建议、三档耐心、来源、门外等待与预约请求、长动作确认的离开人数预测。
- [x] 回归：先观察新增分布测试失败，再实测2000日目标区间、种子重现、旧计划保留及满员三种分支。
- [x] 验收：完整 run.ps1 -Test；实际渲染 shop_ui 两种分辨率并检查截图；更新 docs/features.md。

**审阅重点：** 零期望与大期望；满员后释放空位的事件顺序；门外期限与请求不自动变预约；保存失败不结算；旧档已计划日与来源保留。

**实施选择：** 第0天继续使用既有固定林照晚新手客；自然客分布不再承担每日保底。满员以性格耐心、信任与紧急度形成分数，配置阈值决定门外等候、预约请求或离开。分布目标在无成长、无既有回访的默认客流条件下统计。

**整合修复：** 在线人物仅填充已规划的自然客/burst名额，保留到店时刻、来源、日计划与原占位档案；迟到草稿可留待后续已规划名额。限时加成按有效时间与营业窗口的交集折算。保存JSON使用完整浮点精度；新期望值先通过实际保存编码规范化到稳定值再抽样，避免引擎解析产生微小重载差异，旧计划不受规范化影响。新版流失记录保存扣减前后值及所用参数，支持生成角色的身份/行为来源校验。测试入口仅在本进程启用并还原Conda DLL搜索设置，便于本机Python执行HTTP回归。
