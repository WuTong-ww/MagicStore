# 零点杂货铺本月全量技术分工

**目标验收日为 2026 年 11 月 30 日。** 三位开发者分别负责人物与客流、问卜与事件、经营与工程整合，第四位负责美术。完整构想中的功能都进入本月验收。每项要能从 Windows 游戏界面触发、看到结果、退出重进后继续，或有可复跑的测试存档来验证条件较少见的分支。[完整需求](游戏介绍.md) · [美术制作单](art-brief.md)

基线为 `main` 的 `4b3e267`，使用 Godot 4.6.3、GDScript 和 Compatibility。已有林照晚的单人接待、关键词 Mock、单牌塔罗金币结算、统一时钟与多档保存。当前固定次日回访是演示逻辑。下文是待开发和验收的任务，字段、内容数量、案例情节和术式交互属于建议方案。[现有功能](features.md) · [现有契约](contracts.md)

**在线 AI 按单卡 A100 自部署。** 采用 Qwen3.8-27B 和 vLLM，80GB 优先验证 BF16，40GB 优先验证 W4A16 INT4。A 交 GPU 服务和网关，B 交模型可用的案例规则与候选 ID，C 接 Godot 的 HTTP provider、离线回退和 Windows 包。三组用约定好的样例响应并行开发。[显存选型、部署和验收](ai-deployment.md)

## A 人物、AI 和客流

| 任务 | 本月要做的功能 | 可交付的验收用例 |
| --- | --- | --- |
| A1 人物实例与捏脸 | 固定人物保留手写设定。普通客按原创模板生成，参考客按策划模板生成。档案含身份、职业、生日、星座、MBTI、性格、偏好、出身与经历。玩家与普通顾客共用头像部件，固定人物与特殊角色用预设。存档保存稳定 `npc_id`、外貌部件和每次来店 `visit_id` | 新建两个档，固定人物设定一致而经历独立。随机顾客回来时沿用原姓名、脸和记录。捏脸保存后重开仍一致 |
| A2 关系与记忆 | 先创建关系网和初始亲密度，再生成与之相符的问题和经历。分别保存店长对顾客的熟悉度、顾客对店长的信任、NPC 之间的亲密度。维护历次来店、预测、反馈和各人已知经历，按熟悉度开放追问 | 顾客来问另一位 NPC 的事。后续选择能改变两人的亲密度，熟客能提及旧事。未参与者看不到尚未获知的信息 |
| A3 手写内容与真实 AI | 自部署 Qwen3.8-27B，负责 vLLM、限流网关、提示与输出结构。保留关键人物、故事与口吻，由模型在已知事实、关系和候选范围内生成新顾客、回复、反应与事件提案。按钮和自由输入进入同一意图校验，C 通过现有异步入口接网关 | 在实机 A100 上生成一位原创顾客并多轮交谈。按人物模板核对口吻、既有事实和信息边界。同一意图用按钮及自由输入均可触发，断网可用本地话题继续已有案例 |
| A4 参考家族与稀有性 | 来源与出场方式独立。保存来源作品、参考人物或家族、模板 ID、改写姓名、个人与家族共同背景、成员、辈分、关系、初始亲密度、稀有级别、出场条件、存档实例。入档先建立完整家族，再按条件分批到店。分别配置普通客权重、家族触发、成员数量、同段出场上限和熟客回访。分别统计家族抽中次数与个人初遇比例 | 在可复跑的来客表中，普通原创客占多数。触发一个家族，两名成员先后出现并共享关系。读档继续沿用同一家族和成员 ID。已认识的特殊客依自己的条件回访 |
| A5 客流、推荐与等待 | 日客流受口碑、经验、人物目标、回访、推荐共同影响。记录推荐来源，在顾客卡显示。支持问卜、购物、两者兼有三种来店意图。用游戏分钟更新排队、预约、耐心、离店、流失和回访意愿。耐心由性格、紧急程度、行程和关系共同决定 | 跑出零客日和爆单日。可接待、预约或等待，耗时动作让一位来客离店。停在输入框、看手记或等待 AI 不推进耐心。同一位获推荐的新客显示原推荐人 |
| A6 回访与关系影响 | 接收 B 的事件结果及可披露内容，根据性格、行程、关系决定何时反馈、延迟或不反馈。回访沿用身份、家族、外貌和旧记录。按事件条件应用熟悉度、信任和人物亲密度变化，触发熟客或转介绍机会 | 同一事件可覆盖正常反馈、延期和未反馈。关系变化带原事件或接待引用，重放不会重复累加。顾客在事件发生前不会汇报该结果 |
| A7 经营风格报告 | 累积实际提问、选择、建议、用时和经营记录，达到样本要求后按公开的观察规则形成娱乐性报告。展示样本数和能点回的记录，样本少时给出相应提示 | 两组不同经营行为得到有依据的差异描述。玩家可查报告引用的具体动作，页面标注娱乐用途 |

## B 问卜、术式和事件

| 任务 | 本月要做的功能 | 可交付的验收用例 |
| --- | --- | --- |
| B1 正式服务与问话效果 | 接待中区分闲聊和正式占卜，先确定服务及报酬。为每案提供允许的对话意图、线索和事件分支 ID，按条件核验 A 的候选并记录有效结果。使用各术式前验证已学和适用条件 | 顾客可只问卜，也可问卜后另购商品。付款失败保留未揭牌，成功后同一服务重看原结果。按钮和自由输入能分别触发可追溯效果，超出案例的模型提案被拒绝 |
| B2 信息与推断 | 案例分别记录世界事实、顾客陈述、工具线索、玩家假设和对外预测。预测保存原话、对象、条件和时间窗。记录建议、接受或拒绝及实际行动。玩家只看到有权获知的事实 | 同一句顾客陈述可能偏离事实。玩家根据同一线索可作出不同预测，假设不会变成已确认结论 |
| B3 全部术式 | 实现下表各入口与规则。每项各有交互、至少一种可用线索或服务，以及相应费用和消耗条件 | 新档只会塔罗。正常学习后，每一项都能在适用案例完成一次操作并取得有意义的结果 |
| B4 到期事件与预测反馈 | 按案例条件处理事件，允许建议和商品使用影响行动或结果。分别记录事件是否发生、预测是否符合、是否有足够证据、顾客是否反馈。由事件条件提议信任、复盘成长、礼物、口碑、转介绍及有期限的客流变化，A/C 分别接收相关效果 | 测试符合、偏离、证据不足、事件尚未发生、事件已发生但未反馈。失误可触发信任损失和复盘机会；成功在满足条件时触发奖励。未反馈不会自动判成失败 |
| B5 前世今生 | 设计可学的前世技法。按剧情给固定、普通随机和参考 NPC 关联稳定前世身份、片段、前世关系及今生关联。分别记录已见片段、待验证解释、已确认关联和后续故事 | 同一段前世片段可以被误读，获得补充证据后可核实。多次来店与读档后仍保留已揭示内容；纯今生案例也能独立完成 |

术式操作以下按游戏交互举例，具体排盘、牌库、线索和耗时由策划与 B 在开工时定稿。**暂将紫微盘作为紫微斗数的排盘和查宫界面**，两项都要在游戏里可体验。进阶术式的资源成本高于基础项目。

| 术式 | 建议的操作 | 建议给出的线索或服务 |
| --- | --- | --- |
| 塔罗 | 沿用基础抽牌，可选问话方向 | 当前处境和可继续追问的方向 |
| 雷诺曼 | 选择或比较两张符号牌的组合 | 涉事对象、联系或所处场景 |
| 梅花易数 | 用案例时间或数字起卦，查看变化位置 | 容易变化的条件或关键节点 |
| 易经 | 比较两种卦象或逐爻查看线索 | 行动方案的取舍与限制 |
| 小六壬 | 选择短期时段，查看时序结果 | 一次短期行动的节奏或阻碍 |
| 现代占星 | 用角色出生资料与选定时期查看轮盘 | 较长时期的主题与机会窗口 |
| 八字 | 在四柱界面选看资料组合和时期 | 长期偏向、阶段条件与资源提示 |
| 紫微斗数与紫微盘 | 生成盘面并选宫位查看流年或主题 | 较长时期的关系、事业或其他主题线索 |
| 前世技法 | 解读片段并把线索与前世身份或人物关联 | 可能的跨世关系、纠葛和可查证的记忆 |

## C 经营、成长和整合

| 任务 | 本月要做的功能 | 可交付的验收用例 |
| --- | --- | --- |
| C1 时钟和精力 | 服务、学习、制作、采购或采集、休息等动作统一校验和推进游戏分钟。处理跨时段、打烊、次日回精力及 A/B 的到期事项。记录成本和失败原因 | 精力不足可休息或进次日。某次制作跨过等候期限，A 更新客流。打字、看资料和等模型不改变时间 |
| C2 报酬与账目 | 统一双方钱包和物品账户。支持金币、物品两类正式报酬，并以各自账目区分占卜报酬、商品交易和额外赠礼。报价含本次服务、资源成本和支付方式，确认后一次提交 | 完成只买商品、只问卜、两者结合三条路径。至少一次金币占卜、一次物品占卜和一次额外赠礼能分别查到账。余额或物品不足时维持原状态 |
| C3 库存、采购、赠料和采集 | 储物柜管理商品、原料和来源。原料可从商店购买、作为顾客赠礼获得、外出采集，也可直接出售。支持高级或隐藏原料的条件。采购、销售、采集和制作使用同一库存 | 三种途径各获得一种可用原料。把其中一份卖掉后，制作只能消耗剩余库存。采集点随资源与时间条件变化 |
| C4 需求、研究、制作与使用 | 开局供应少量商品。顾客有需求却无适用商品时，可登记，结束接待后研究配方。配方由配置组合原料。药水、水晶、香氛为形态，物理、心理、环境为用途，字段独立。商品可提升属性、改变事件条件或提供新解决方式。保存交易、使用和反馈关联 | 接待中登记需求，之后解锁配方、获得原料、制作、出售并跟踪使用结果。至少有一个用例支持属性效果，一个改变事件条件，一个开放新选项。用同一物品记录串回交易与反馈 |
| C5 技能、复盘与店铺成长 | 初始只开塔罗。配置每项学习的金币、精力、游戏时间、前置和已解锁状态，涵盖全部术式及前世技法。应用符合条件的复盘成长、经营经验、赠礼、口碑与有时限的客流影响，供 A/B 查询 | 缺前置或资源时有提示，成功学习后 B 可使用该术式。错误判断能按条件获得复盘成长；成功服务产生的口碑或客流加成按期限生效 |
| C6 公共接入、保存和发布 | 维护动作、事务、旧档和七场景，按素材键挂接角色与术式。接入自建网关的地址配置、HTTP 超时、取消、迟到响应校验和离线模式。保留多档、备份、原牌和未结束接待，导出 Windows 版 | 原型旧档和新档均可读。交易、剧情和队列重开后保持。真实与离线模式均可启动，失败写盘、重复点击、超时和切档回包通过测试。七场景在导出包可进入和返回 |
| C7 商品素材扩展 | 接入美工原创的商品与原料样例。用样例和规格指导 AI 产生候选，人工筛选后用同一素材清单导入；保留来源、版本与 `item_id` | 以原创样例实际扩出一组可用商品或原料图。小尺寸可辨认、风格一致，导入后正确对应配方、库存与交易 |

## 三人如何同时开工

| 共享数据 | 交接责任 | 第一天可用的假数据 |
| --- | --- | --- |
| 人物、档案与来店 | A 给 B/C `npc_id`、`visit_id`、`case_id`、来店意图及公开资料。关系和记忆归 A，双方钱包和库存归 C | 林照晚、关系人、普通购物客、同一家庭的两位成员 |
| AI 网关 | A 给 C 结构化回复、草稿及失败码，B 给 A 本案的允许范围。C 关联 `request_id`、`action_id` 与状态版本，游戏规则最终决定是否提交 | 合法对话、无效线索、超时和切档后回复四种样例 |
| 服务报价与结算 | B 提议服务与可用线索，C 校验并结算。一个 `service_id` 绑定报价、报酬、牌面和时间；追加正式占卜生成另一笔。存档成功后才展示结果 | 现金充足、物品充足、支付不足三组报价 |
| 事件与反馈 | B 保存 `prediction_id`、`event_id`、到期分钟和可披露结果。A 安排反馈，C 入账条件满足的礼物、口碑及成长。反馈、影响、赠礼各带关联 ID | 同一事件分别设为正确反馈、错误反馈、延期、不反馈 |
| 商品与能力 | B 给 C `demand_id`、使用条件和案例触发点；C 提供已学术式、库存与 `item_use_id`。B 判使用结果，A 读取受影响的关系和记忆 | 一条待研发需求、一个物品效果、已学及未学的术式 |
| 游戏时间 | C 提供动作前后 `clock_minutes` 与 `state_version`。A 处理队列、预约和回访，B 处理到期事件，按分钟和稳定 ID 决定同一分钟的顺序 | 一次行动跨过来客截止点、一次打烊跨过事件到期点 |
| 贴图和面板 | A 交 `visual_key`，B 交术式、`card_id`、证物与前世片段键，C 交 `item_id` 和场景键。美工按这些键出图 | 使用现有 SVG 及各组占位图，按相同键替换 |

`save_id`、`npc_id`、`visit_id`、`action_id`、`clock_minutes` 和 `state_version` 沿用现有契约。其余字段名是建议。C 先接薄层公共接口；A、B 在各自目录交付模块、规则和界面。用 `GameState` 汇总业务结果和耗时，核心校验完整候选、写盘成功再发布状态。重试同一动作或重新读档不会再次收费、补发奖励或改变已抽出的牌。

当前加载器和存档校验只接受一个 `npc_lin`。多人物、家族和新账目需要共同升级配置和存档。C 维护 `game_state.gd`、`save_service.gd`、`content_loader.gd`、公共场景与契约，A/B 提供各自校验规则。迁移保留旧档的金币、精力、时间、原牌、经历和活动接待。原型没有记录过的预测与事件在旧档标明为空，供玩家继续新接待。[现有存档契约](contracts.md)
